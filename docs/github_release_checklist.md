# GitHub release checklist

## Before creating a public repository

✅ Code:

- package installs with `pip install -e ".[dev]"`
- `pytest -q` passes
- demo pipeline runs from a clean clone
- CLI help is readable
- no hard-coded local Windows paths in package code

✅ Data:

- no private clinical data committed
- no large H5AD/RDS/FASTQ/BAM files committed
- every public dataset has accession/DOI, license/terms, and checksum
- download script can recreate the local `data/external` tree

✅ Reproducibility:

- `Dockerfile` builds
- `envs/environment.yml` works
- CI runs tests and demo
- all figure/table outputs are generated by scripts

✅ Metadata:

- `LICENSE` present
- `CITATION.cff` filled with real authors and repository URL
- `.zenodo.json` filled with real authors
- `README.md` includes install, quick start, input schema, output schema, and
  limitations

## Suggested first GitHub commands

Run from WSL after you confirm the repository name and account:

```bash
cd /mnt/e/4实验数据/10新算法/SheafSignal
git init
git add .
git status
python scripts/release_audit.py
git commit -m "Initial SheafSignal reproducible methods package"
gh repo create SheafSignal --public --source=. --remote=origin --push
```

⚠️ Do not run the final `gh repo create --public` step until all author names,
data permissions, and repository visibility are confirmed.
